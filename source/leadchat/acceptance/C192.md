# C192. Один диалог Avito от ответа до карточки

В обоих оформлениях LeadChat запуск выполнялся из встроенной вкладки. Для каждого сценария весь путь проверен на одном синтетическом CID. Стенд использовал ядро C190, API C160, вкладку C180, расширение 2.8.47 и модуль доставки worker из сверенного комплекта C165.

1. Ответ прошёл отдельную проверку. Тестовый получатель получил его один раз. Worker восстановил сохранённую квитанцию и сохранил доставку в LeadChat.
2. До согласия клиента план вернул ожидание. Работы по созданию заявки в CRM ещё не было. Затем в тот же диалог добавлено входящее сообщение с явным согласием и обязательными сведениями. План и форма использовали новое состояние исходного диалога.
3. Расширение запросило проверку дублей по номеру из формы. После тестового ответа об отсутствии дублей отправило одну форму и прочитало сохранённую карточку. Поля совпали, включая «Отзыв» для партнёра 624. До проверки карточки диалог оставался открыт.
4. После потери подтверждения карточки выполнены остановка и новый запуск. Расширение читало статус исходной операции, поэтому сохранились исходный ID карточки и один запрос на создание. Старое разрешение получило HTTP 409. В конце запуск остановлен из вкладки.

В первом прогоне стенд загрузил модуль доставки из копии API. Он сделал ещё один вызов тестового получателя после сохранённой квитанции. Проверка показала, что API ставит сообщения в очередь ARQ. Фактическую отправку выполняет worker. Финальный прогон использовал сверенный по SHA-256 модуль worker C165. Повторный вызов получателя не воспроизвёлся.

Прошли два полных сценария и пять регрессий C191. Ответы модели, Avito и CRM были тестовыми. Сетевых обращений за пределы стенда и вызовов Telegram не было. Ruff, форматирование, mypy и проверка синтаксиса JavaScript прошли.

Рабочая установка и живая приёмка остаются отдельными условиями запуска.
